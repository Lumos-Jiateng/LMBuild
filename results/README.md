# Results

All scores use the final metrics **v3.8** ([`docs/evaluation/metrics_v38_changes.md`](../docs/evaluation/metrics_v38_changes.md)).

- `scores/all_scores.csv`: one row per scored design (38,412 rows), for every system and setting of the study.
  - Key columns: `task`, `key` (the run key), `system`, `family` (closed / open / generator), `tier` (A, B, C, or `ext`
    for a one-shot generator), `condition`, `trajectory_rounds`, and `checkpoint` (`final`, or `1`/`2`/`3` for the
    round checkpoints).
  - Metric columns: the twelve metrics `S.1`–`R.3`, each in [0, 1], and a `<metric>_status` column next to each
    (`pass`, `degraded`, `fail`, `skipped` or `n/a`). An empty metric cell with a status means the dimension does not
    apply to that design; an empty cell with an empty status means the design has no record in that metric's record
    set (the main table counts it 0, as a missing design).
  - `task_set`: `orig50` (the first 50 tasks of `benchmark/core_v2.json`) or `new150`.
  - `main200`: the records the 200-task main table may score for a (system, task), ranked (1 preferred, 2 fallback):
    for the original 50 the round-1 checkpoint of the 3-round trajectory, or its final design when the episode ended
    inside round 1; for the new 150 the one-round run or its round-1 checkpoint; for generators the image output, else
    the name-only one. Per metric the table takes the best-ranked record present in that metric's record set.
  - The file is written by `scripts/export_scores.py` from the evaluation records (record sets `eval_v34l1`,
    `eval_v38l2`, `eval_v345`, `eval_v35`, `eval_v38p2`, `eval_v38p3`).
- `scores/metrics_before_v38.json`: the pre-audit 200-task means (fixed numbers, the "before" column of the
  metric-audit table).
- `tables.md`: the paper's tables, generated by `python scripts/make_tables.py --latex results/paper`: the 200-task main
  table, original 50 vs new 150, the published 3-round setting on the original 50, the stratified 50-task resamples
  (seed 20261002; 13 + 37 and 12 + 38 objects with / without a catalog sheet; 1,000 draws), ranking validity, and the
  ablations (Tier A / C, round checkpoints, prompt richness).
- `paper/`: the same tables as LaTeX (main table, resample results, resample correlations, metric audit).
- `v2/<task>/`: what the evaluator needs to score new designs on that task.
  - `task_snapshot_core.json` is the task as frozen for the runs. Only its paths were rewritten for this layout.
  - `anchors_v34l1.json` holds the stability targets from the reference (Level 1 v3.4); `anchors_v33.json` the v3.3 ones.
  - `afford/sheet_v3{6,7}.json` are the Level 2 population sheets.
  - `reference_eval_*.json` are the reference object's own scores.
  - `judge_l3/{qwen2.5-vl-32b,gemma-3-27b}.json` are the two judges' stored answers.
- `human_study/eval_v34/<task>/`: the computed Level 3 records of the 90 human-study designs, so that `calibrate_l3` can be refit. They are kept outside `v2/` so that the evaluator never tries to rescore designs that are not shipped.

`make_tables.py --latex` on the shipped `all_scores.csv` reproduces `paper/*.tex` byte for byte; the 200-task means,
the resamples and the validity statistics were checked against the authors' working evaluation (differences below
1e-4 before rounding).
